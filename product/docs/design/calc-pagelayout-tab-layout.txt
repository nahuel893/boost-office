CALC - PAGE LAYOUT TAB LAYOUT (Tabbed Office, remaining tabs, task L1)
======================================================================
Status: DESIGN for task T3; the implementer follows this file verbatim. Nothing built yet.
Date: 2026-10-15. Reference: Excel for Microsoft 365, Windows, 2024+ look, window 1920 px:
product/docs/research/2026-10-15-excel365-ribbon-reference.md section 2; images in
/mnt/games/libreoffice/assets/excel-ref/page-layout/ (never committed).
Same tools and rules as product/docs/design/calc-data-tab-layout.txt: gen_ribbon.py layout,
Fluent "boost" icons, compact rows. Every Excel control is on the tab, in Excel's order: an
existing LibreOffice command, a new dropdown/split command, or a greyed PLACEHOLDER (a real
always-disabled slot, label = Excel label, tooltip "<Label> (not available yet)").
Every .uno: command named here was checked against CalcCommands.xcu / GenericCommands.xcu and
sc/sdi + svx/sdi + sfx2/sdi (exists, and a Calc shell implements it) unless marked "verify".
Ground truth: the 2024+ per-group crops page-layout-bettersolutions-1..5.png (no full-width 365
screenshot exists for this tab); page-layout-exceldemy-1.png (2023, narrow) shows the order.
This page replaces LibreOffice's "Layout" tab; T1 renames it "Page Layout".

LEGEND
------
  +--------+
  | ICON   |    L  LARGE button: 32 px icon, label below          (json style "large")
  +--------+
  (x) Label     S  SMALL button: 16 px icon, label to the right   ("small-label")
  (x)           I  SMALL button: icon only, tooltip = the name    ("small")
  v             DROPDOWN: the whole button opens a menu
  |v            SPLIT: the body runs an action, the arrow opens a menu
  [P]           PLACEHOLDER: greyed out until the feature is implemented

  Columns of the control tables:
    #, pos      order on the tab; c<column>r<row> inside the section
    Excel       Excel's control, size (L/S/I) and kind (btn, tgl, chk, dd, split, combo, spin)
    here        size and kind on our ribbon (dd = dropdown, tgl = toggle shown pressed;
                checkboxes become toggle buttons: gen_ribbon only makes tool buttons)
    kind        existing   LibreOffice command used as is (LibreOffice's own label)
                variant    existing command with URL arguments (".uno:X?Arg:type=v"), with its
                           own label/tooltip node in CalcCommands.xcu; config only, no new slot
                NEW DD     new dropdown command: CalcCommands.xcu label, Controller.xcu Popup +
                           ToolBox (GenericPopupToolbarController) nodes, popup xml; no slot
                NEW SPLIT  new body slot (Data recipe, same Execute/state as the original) +
                           new "...Menu" popup command opened by the arrow
                NEW ALIAS  new slot that mirrors an existing slot only to carry Excel's label
                PLACEHOLDER always-disabled slot (Data recipe); a "family slot" is one slot shared
                           by several URL variants ".uno:Base?Arg:string=value", each with its own
                           label and tooltip (see the overview: the slot budget forces this)
                "slot +N" = SID_NEW_SLOTS+N in sc/inc/sc.hrc (allocation table in the overview)
    label       text on the button: LibreOffice's "Label" without "~" and "..." for existing
                commands (as on the Data tab), Excel's label for new commands
    icon        B boost icon exists; A alias of an existing boost icon (no new art);
                C Colibre icon exists and shows today, boost icon to add for consistency;
                N no icon anywhere, boost icon required before the tab ships.
                Then the Fluent 1.1.344 glyph (every name checked in
                /mnt/games/libreoffice/assets/fluent/package/icons/).
    json id     for URL variants the json "cmd" is a short id and "action" holds the URL;
                the icon comes from the item's "icon" key (e.g. "cmd/32/insertcharttype_map.png",
                boost manifest name "<base>_<value>"), which avoids the escaped "%3f" file names.

  Notes
  - Orientation: verified. Calc's document shell implements .uno:Orientation with the boolean
    argument isLandscape (sc/sdi/docsh.sdi:88, sc/source/ui/docshell/docsh4.cxx:603; svx.sdi
    declares "SfxBoolItem isLandscape"). The two items are URL variants with labels "Portrait" and
    "Landscape" in CalcCommands.xcu. TRAP: never put .uno:Orientation itself on the ribbon:
    Controller.xcu registers a module-less toolbox controller for it (lo.writer.
    PageOrientationToolBoxControl, in the Writer library). Menu items are not affected.
  - Size: verified. .uno:CalcPageSize (SID_SC_ATTR_PAGE_SIZE, docsh.sdi:90, docsh4.cxx:665) takes
    PaperFormat (UInt16 = the i18nutil "Paper" enum, include/i18nutil/paper.hxx: A3=3, A4=4, A5=5,
    LETTER=8, LEGAL=9, TABLOID=10, ENV_DL=17, EXECUTIVE=23, ENV_10=28, B4_JIS=34, B5_JIS=35,
    STATEMENT=38). Each size is a URL variant with Excel's name as label. "More Paper Sizes..."
    is LibreOffice's Page Style dialog.
  - Margins: SPIKE in T3. .uno:CalcPageMargin (SID_SC_ATTR_PAGE_MARGIN, docsh4.cxx:727) needs an
    SvxLRSpaceItem and an SvxULSpaceItem (both declared "Page" in scalc.sdi:6659). sfx2 accepts
    complex arguments as "<Name>.<Member>" properties (sfx2/source/appl/appuno.cxx:350) and URL
    arguments as name:type=value (sfx2/source/control/unoctitm.cxx:431), so the three presets
    are written as URL variants with 1/100 mm values (Excel Normal: left/right 0.7", top/bottom
    0.75"; Wide: 1" all; Narrow: left/right 0.25", top/bottom 0.75"; header/footer distances
    are not set by this command). If the spike fails, drop the three presets: the menu keeps
    "Page Style..." only. Do NOT spend placeholder slots on them (budget).
  - Print Area v: LibreOffice's four print-range commands. In a menu LibreOffice shows the
    ContextLabel, so the items read "Define", "Clear", "Add", "Edit..." (as in the menu bar's
    Format > Print Ranges). "Edit..." is a LibreOffice extra.
  - Breaks v: Excel's "Insert Page Break" acts on the row and column of the cell cursor;
    LibreOffice has separate row and column breaks, so the menu uses the menu bar's two submenus
    (.uno:InsertBreakMenu, .uno:DelBreakMenu; their items' ContextLabels both read "Row Break" /
    "Column Break", which is why submenus are needed) plus "Delete Page Breaks" (Excel: Reset All
    Page Breaks).
  - Background: placeholder. A page style has a background, but it only prints; Excel's sheet
    background is a picture shown behind the cells on screen.
  - Print Titles: NEW ALIAS .uno:PageLayoutPrintTitles, slot SID_NEW_SLOTS+16
    (FID_PAGELAYOUT_PRINT_TITLES), label "Print Titles". It mirrors SID_OPENDLG_EDIT_PRINTAREA
    (.uno:EditPrintArea, whose label is just "Edit"): the Edit Print Ranges dialog has "Rows to
    repeat" and "Columns to repeat". Mirror the slot in every interface that lists the original:
    TableSelection (docsh.sdi:23, Execute/GetState in tabvwsh3.cxx), drawsh.sdi:35 and
    drtxtob.sdi:32 (StateDisableItems). Simplest Execute: dispatch SID_OPENDLG_EDIT_PRINTAREA.
    No code calls Invalidate(SID_OPENDLG_EDIT_PRINTAREA) on its own (checked with rg), so no
    invalidation mirror is needed. Config-only fallback if T3 wants no C++: a URL variant
    ".uno:EditPrintArea?PrintTitles:bool=true" with its own label (verify that the slot ignores
    the unknown argument and keeps its state).
  - Excel's Page Setup dialog launcher is not built (no launchers in gen_ribbon); the Margins and
    Size menus end with "Page Style...", which is the same dialog.
