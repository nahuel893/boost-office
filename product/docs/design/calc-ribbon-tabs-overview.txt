  Help instead of after it, as Excel does; they are out of scope. Open question 2.
  Mnemonics: P is taken by ~Print (contextual) and M by ~Media, so "Page ~Layout" keeps L,
  "For~mulas" uses M like Excel (clash only while the Media tab shows), "Hel~p" uses P (clash only
  while Print preview shows). Upstream already has clashes (F File/Functions, D Data/Draw, R
  Review/Form).

4. RECIPES USED (details in product/docs/calc-data-redesign.md section 3)
-------------------------------------------------------------------------
  Dropdown      CalcCommands.xcu label + Controller.xcu Popup node (ResourceMenuController, Value =
                popup xml name) + ToolBox node (GenericPopupToolbarController) + popup xml in
                sc/uiconfig/scalc/popupmenu/<tab>_<name>.xml + sc/UIConfig_scalc.mk. No slot.
  Split         body slot with the original's Execute/state (+ invalidation mirrors) + "...Menu"
                popup command; ToolBox node on the body with Value = the menu (as HomeMergeCenter).
  Alias         like a split body without the menu: a new slot only to carry Excel's label.
  Placeholder   scalc.sdi entry (Menu/ToolBox/AccelConfig FALSE), cellsh.sdi StateMethod only,
                always-DisableItem case in cellsh.cxx, label + "(not available yet)" tooltip.
                Family: one slot; one xcu node per variant URL (escape "&" as "&amp;" in xcu/xml).
  URL variant   xcu node named with the full URL (precedent: .uno:ConditionalFormatEasy?FormatRule:
                short=2, .uno:StyleApply?Style:string=...); on the ribbon the json item uses "cmd" =
                a short id and "action" = the URL (gen_ribbon already supports "action").
  Icons         boost manifest entries; for URL variants use the json "icon" key with a plain name
                (cmd/32/<base>_<value>.png, cmd/sc_<base>_<value>.png) instead of LibreOffice's
                escaped names (cmd/32/insertcharttype%3ftype%3astring=map.png).
  Removed       remove_objects: "Menu Insert", "Menu Page", "Menu Review", "Menu View" (the GtkMenu
                objects of the old overflow buttons; only those buttons referenced them). Keep
                "Menu Help" (File tab) and "Menu Statistic" (unreferenced upstream leftover).


5. RISKS FOR IMPLEMENTATION
---------------------------
  R1  Slot ceiling. After this slice 4 ids remain in the whole Calc range. A later fork-only
      command that is not a placeholder must reuse a placeholder's slot or take an upstream gap
      (+3..+9, +17..+19, +23, +25, +28..+30, +35, +48, +57, +75..+78, +89..+94), which upstream
      could reuse. Families are what makes this fit; they bend the "one slot per placeholder" ruling.
  R2  URL variants are new to the product tooling. gen_ribbon handles "action", but the unit tests
      (labels, controllers, image flag, icon coverage, placeholder lists) and the UITests key on
      ".uno:" + cmd. T2 extends them first; every family variant must be checked disabled.
  R3  Unknown URL arguments: .uno:InsertSparkline?Type (T2) and the optional EditPrintArea alias
      fallback rely on sfx2 ignoring an argument the slot does not declare. Verify on a dbgutil
      build (no assertion, button still enabled). Placeholders have no Execute, so for them the
      argument never matters.
  R4  Margin presets: complex items (SvxLRSpaceItem/SvxULSpaceItem) through URL arguments are
      unproven. T3 spike; fallback drops the three presets (no slot spent).
  R5  Formulas' eight category menus need one new C++ popup menu controller (registration in
      Controller.xcu and in a component file, function manager access, LRU list). Largest code
      item of the slice. Fallback: static menus, no slot.
  R6  First product popups with submenus (Shapes: ToolbarAsMenuController submenus; Breaks:
      menu-bar submenus; More Functions: dynamic submenus) opened from a ribbon dropdown. Verify early.
  R7  Switch Windows reuses framework's WindowListMenuController under a new command name. Verify;
      fallback is a static popup.
  R8  .uno:Orientation has a module-less Writer toolbox controller: it must never appear as a
      ribbon item (only as menu items with arguments).
  R9  Menu check marks for Automatic/Manual (two variants sharing one boolean state) may both show
      checked; fallback to one AutoCalculate toggle.
  R10 Width: Insert is estimated at ~1847 of ~1875 px; T2 measures at 1920 and applies the fallback
      ladder (Filters, then Sparklines to small columns). Spanish labels will push the right-most
      sections of every tab behind ">>" sooner.
  R11 Icons: 88 icons must exist before their tab ships (otherwise large buttons show only text and
      change width); 43 more for consistency. That is about twice the Home icon set. Each tab task
      carries its own icons; the C ones may follow in a polish pass.
  R12 Widget ids must be unique in the whole .ui. Prefixes differ per page, but T-tasks should run a
      whole-file duplicate id check (two pages use .uno:Navigator, .uno:ToggleSheetGrid and
      .uno:ViewRowColumnHeaders under different prefixes, which is fine).
  R13 New strings (three tab labels and about 115 new CalcCommands.xcu nodes for dropdowns,
      placeholders and variants) are en-US only; translations are out of scope but block
      shipping, as for Home and Data.
  R14 LibreOffice-only buttons leave the tabs; several are reachable only from the classic menu
      bar, which in this mode is shown with the first quick access button (.uno:Menubar). The
      most used one is Automatic Spell Checking (Review); see each tab's list.
  R15 Size: each tab task (layout + xcu + popups + slots + icons + tests) will exceed the 400-line
      heuristic; plan chained PRs per tab.
